## 1. 这是什么

一个 Windows 桌面端的 **NAS 管理工具箱**。它把「看 NAS 是否在线、里面忙不忙、盘满没满、容器跑没跑」这几件天天要做的事,收在一个窗口里完成。

| 你能做的事 | 在哪个页面 |
|---|---|
| 登记多台 NAS,随时看在线 / 离线 | 设备管理、首页 |
| 看 NAS 的系统 / 在线时长 / 负载 / 温度 / 内存 / 磁盘占用 | NAS 状态 |
| 测连通性与局域网网速 | 网络诊断 |
| 看本机磁盘空间、列出并打开 NAS 的 SMB 共享 | 磁盘与共享 |
| 查看 / 启停 / 部署 Docker 容器、Compose 项目、镜像与网络 | Docker |
| 一键启动自己收集的 NAS 绿色工具(WinSCP、PuTTY…) | 工具库 |

设计取向:**只读优先、不做隐蔽改动**。状态采集用的全是只读命令;所有会改动 NAS 的操作(启停容器、删除镜像、下线 Compose)都必须你手动点击,并且都有二次确认。

## 2. 运行环境与安装

### 系统要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 版本 19041(20H1)或更高 / Windows 11 |
| 架构 | x64(同时也提供 x86 / ARM64 构建) |
| 运行时 | **便携版无需预装任何东西**(WinAppSDK 运行时已随包自带) |
| 从源码运行 | 需 .NET 10 SDK(`winget install Microsoft.DotNet.SDK.10`) |

### 安装方式

**方式一:便携版(推荐给普通用户)**

解压发布包到任意目录,双击 `NasToolbox.exe` 即可。不写注册表、不需要管理员权限、卸载就是删文件夹。

**方式二:从源码运行(给开发者)**

```powershell
cd NasToolBox
dotnet run
```

### 启动后会立刻发生什么

1. 读取设备台账。**如果台账里已有设备**,程序会在后台立刻检测一遍所有设备的在线状态,结果落盘,下次启动先显示上次结果,不会一打开就是一片灰。
2. 如果你已经指定过「当前管理设备」,程序还会在后台提前采集一次这台 NAS 的状态。等你点开「NAS 状态」页时数据已经就绪,基本是秒出。

这两件事都在后台进行,不阻塞界面。刚打开时看到「检测中…」属于正常现象。

## 3. 界面导览

### 3.1 标题栏与统一搜索

窗口顶部是一条**一体化标题栏**(不是系统默认白条),左侧是应用名,中间偏左是搜索框:

> 搜索设备 / 工具...

它同时搜两类东西:

- **NAS 设备** —— 匹配显示名、IP / 主机名、Hostname、备注,最多给 4 条
- **工具库** —— 匹配工具名、分类名、描述,最多给 6 条

下拉建议里用前缀区分类型,例如 `设备 · 群晖` 与 `工具 · WinSCP`。

**回车行为**(容易踩的一点):

| 你输入的方式 | 回车后去哪 |
|---|---|
| 从下拉里选中「设备 · xxx」 | 跳到**设备管理**页,并自动按关键词过滤列表 |
| 从下拉里选中「工具 · xxx」 | 跳到**工具库**页,并自动按关键词过滤 |
| 直接敲关键词回车(没有选中建议项) | 默认按 **工具**搜索,跳到工具库页并过滤 |

也就是说:**想搜设备,请一定要点选下拉里带「设备 · 」前缀的那一条。**

### 3.2 左侧导航

| 菜单 | 页面 |
|---|---|
| 首页 | 本机信息 + NAS 设备在线速览 |
| 设备管理 | 增删改设备、配置 SSH、手动检测 |
| NAS 状态 | 经 SSH 采集的运行状态 |
| 网络诊断 | Ping、局域网测速 |
| 磁盘与共享 | 本机磁盘 + SMB 共享浏览 |
| Docker | 容器 / Compose / 镜像 / 网络 |
| 工具库 | 第三方绿色工具的启动面板 |
| 关于 | 版本、数据位置、使用须知 |

### 3.3 「当前管理设备」—— 先搞懂这个概念

这是整个工具最重要的一个约定:

> **功能页(NAS 状态 / Docker / 网络诊断 / 磁盘与共享)默认操作哪台 NAS,取决于「当前管理设备」。**

- 在**设备管理**页,每台设备右侧有一个**「当前管理」复选框**。勾上一台,其它台会自动取消 —— **同一时间只有一台生效**。
- 勾选后立即保存,并显示在页面顶部的提示文字里:「当前管理:nas」。
- 从没勾过也没关系:程序会回退到台账里的**第一台**,并在顶部提示「未指定当前设备,功能页将默认使用第一台」。
- 在这些功能页里**手动切换设备下拉框**,同样会把这台写成「当前管理设备」,各页保持一致。

`NAS 状态`页面顶部的「设备」下拉、`Docker`页面的「设备」下拉,默认都会选中这台。

## 4. 五分钟上手

### 第 1 步:添加设备

1. 左侧进「设备管理」,点右上角**添加设备**。
2. 在「基本信息」里填 **IP 地址 / 主机名**(必填),例如 `192.168.1.10`。
3. 如果暂时不想用状态 / Docker 功能,到这里就可以直接**保存**了 —— 首页和设备页已经能看在线状态。

### 第 2 步:配置 SSH(想用状态采集 / Docker 才需要)

在同一个对话框的「SSH 连接」卡片里:

| 字段 | 怎么填 |
|---|---|
| SSH 端口 | 默认 `22`,改过端口才需要动 |
| SSH 用户名 | 群晖建议用 administrators 群组成员账号 |
| 认证方式 | 「密码」或「私钥文件 (id_rsa / .pem)」 |
| SSH 密码 / 私钥路径 + 私钥口令 | 按上一步选的认证方式填 |

**前提**:NAS 上必须先开启 SSH 服务。

- 群晖 DSM:控制面板 → 终端机和 SNMP → 启动 SSH 功能
- 威联通 QTS:控制台 → 网络和文件服务 → Telnet / SSH

### 第 3 步:点「测试连接」验证

表单右上角的**测试连接**会用你当前填的内容真连一次(不保存、不落地),并把结果就地显示在 SSH 卡片下方:

- 成功:`连接成功` + 分阶段耗时(如 `TCP 38 ms · 认证 210 ms`)
- 失败:`连接失败 · 端口未开放` 之类的**具体原因标签**,下面还会跟一句**修复建议**

如果是**第一次连这台设备**,会提示「需确认主机指纹」,并显示主机密钥类型与 SHA256 指纹,同时给一个**信任此指纹并重连**按钮。指纹没问题就点它,之后就记住了。

### 第 4 步:勾选「当前管理」

回到列表,在这台设备右侧勾上**当前管理**。

### 第 5 步:开始用

- 回「首页」看本机信息和设备速览
- 进「NAS 状态」看系统 / 内存 / 磁盘 / 网络
- 进「Docker」管理容器

## 5. 设备管理

### 列表每行长什么样

```
● nas (2)            在线 · 192.168.1.10 · 2 ms        [当前管理 ☑]
  192.168.1.10
  nas
  admin@192.168.1.10:22 · sudo
  4 盘位,RAID5                                 [编辑] [删除]
```

- **圆点 + 状态文字**:灰点「未检测」/「检测中…」,绿点「在线 · 详情」,红点「离线 · 详情」。详情通常是 ping 到的地址与延迟(如 `192.168.1.10 · 2 ms`),Ping 不通但端口可达时是 `SSH 22 可达 · 3 ms` 这类文字,都不通则是「Ping 与常用端口均无响应」。下次启动会先显示上次的结果。
- **第二行**:设备的 IP / 主机名(即你填的那个地址)。
- **第三行**:原始主机名 —— **仅当它与显示名不同时才出现**(典型场景是重名被加了 `(2)` 后缀时)。
- **第四行**:SSH 配置摘要,形如 `admin@192.168.1.10:22 · sudo`,选了私钥会多一个 `私钥`,权限模式选 root 会话则显示 `root 登录`。没填用户名时不显示。
- **第五行**:备注。
- 右侧:**当前管理**复选框(见 3.3)。

### 顶部按钮

| 按钮 | 作用 |
|---|---|
| 添加设备 | 打开空白表单 |
| 全部检测 | 立刻检测所有设备,行上先显示「检测中…」给出即时反馈 |
| 断开 SSH | **清空所有设备上缓存的 SSH 连接**。改过 NAS 账号密码、或连接状态不太对时点它,下次执行命令会重新握手 |

另外:进入本页会先显示上次的检测结果,再在后台自动检测一次(自动检测不会把行置成「检测中」,避免闪烁)。**重复点击左侧「设备管理」菜单也会立刻刷新一次在线状态。**

### 添加 / 编辑设备表单(逐字段)

表单分四张卡片。

#### 基本信息

| 字段 | 说明 |
|---|---|
| IP 地址 / 主机名(必填) | 例 `192.168.1.10`。也可以填主机名,但主机名依赖路由器解析,排查问题时**建议优先用 IP** |
| Hostname(可选) | 填了就直接作为设备显示名;**留空则首次连接成功后自动执行 `hostname` 并回填**。留空期间显示名就是 IP |
| MAC 地址(唤醒用,可留空) | 只做格式校验,格式为 6 组十六进制字符,例 `AA:BB:CC:DD:EE:FF` |
| Web 管理端口(必填) | 常见端口:群晖 5000 · 威联通 8080 · 铁威马 8181 · UnRAID / TrueNAS 80 · OpenWrt 80;Web 管理页按 `http://主机:端口` 打开。设备在线检测在 Ping 不通时会拿该端口做 TCP 探测 |

> 注意:**设备名称没有单独输入框**。有 Hostname 就用 Hostname,没有就显示 IP,连接后会补上真实主机名。台账里不允许重名的显示名 —— 两台都叫 `nas` 时,第二台会自动显示成 `nas (2)`。

#### SSH 连接

| 字段 | 说明 |
|---|---|
| 测试连接 | 用当前表单内容直接连一次,分阶段显示耗时和失败原因,不打断填写 |
| SSH 端口 | 1–65535,默认 22 |
| SSH 用户名 | 例 `admin` / `root`。填 `root` 时会提示「当前 SSH 用户已是 root,无需再提权」 |
| 认证方式 | 二选一:**密码** / **私钥文件 (id_rsa / .pem)**。选私钥后会多出「私钥文件路径」和「私钥口令」两项 |
| SSH 密码 | **编辑时留空 = 保持已保存的密码不变**(这是故意的设计,避免每次编辑都重填) |
| 私钥文件路径 | 支持环境变量,例 `%USERPROFILE%\.ssh\id_rsa`;旁边有**浏览…**按钮。支持的扩展名:`.pem` `.key` `id_rsa` `id_ed25519` `id_ecdsa` |
| 私钥口令 | 私钥本身没加密就留空 |

#### 权限与高级

**权限模式是三选一互斥单选**,避免出现「root 会话 + 关闭 sudo」这种自相矛盾的组合:

| 模式 | 含义 | 什么时候用 |
|---|---|---|
| 普通用户 | 以登录账号身份执行,适合读取类命令 | 只做状态查看 |
| sudo 提权 | **每条命令自动加 sudo** | `smartctl`、`docker` 等常需 root 的命令 |
| root 会话 | 连接后执行 `sudo -i`,之后所有命令都在 root 会话里 | 想要最省事、命令都要权限 |

> 新建设备时**默认选的是「root 会话」**,因为 NAS 管理命令大多需要提权。
>
> 选了 root 或 sudo 才会出现 **sudo 密码**框。它的说明文字会告诉你当前状态:
> - 已保存过 → 「已保存 sudo 密码,留空保持不变」
> - 没保存过 → 「未保存;留空将在 NAS 上尝试免密 sudo(`sudo -n`)」

**命令超时(秒)**:范围 1–600,默认 20。单条命令超过该时长即中断;SMART 全盘检测这类慢命令可以调大。

#### 其他

- **备注**:例「4 盘位,RAID5」。
- **清除已保存的密码 / 私钥口令 / sudo 密码**:勾选后保存会清空本机加密保存的凭据,**并移除该主机的主机指纹记录**。仅在**编辑**已有设备时出现 —— 新增设备没有旧凭据可清。

### 删除设备

点**删除**,会弹确认框并显示设备名与地址。删除设备时会一并丢弃它缓存的 SSH 连接。

### 表单校验规则(填错会看到的提示)

- IP / 主机名为空 → 「IP / 主机名为必填项。」
- MAC 格式不对 → 「MAC 地址格式无效,应为 6 组十六进制字符(例 AA:BB:CC:DD:EE:FF),或留空。」
- SSH 端口越界 → 「SSH 端口必须是 1–65535 的整数(默认 22)。」
- 超时越界 → 「命令超时必须是 1–600 之间的整数秒(默认 20)。」
- 私钥路径不存在 → 「私钥文件不存在:<展开后的完整路径>」

## 6. 首页概览

进页面即可看到两块内容。

**本机信息**(在当前电脑上采集,与 NAS 无关):

主机名、本机 IPv4(多网卡会并列显示)、默认网关、处理器型号、内存总量(GB)、操作系统、开机时长。

其中网络信息是即时读取的,CPU / 内存 / 系统 / 开机时长走 WMI 查询(稍慢,放后台线程);取不到就显示「未知」。

**NAS 设备信息**:

列表显示所有设备与在线状态(同设备管理页的圆点规则),先显示上次的缓存结果。右上角**检测全部**会重新测一遍。

没有任何设备时,列表位置会提示「还没有 NAS 设备 —— 到左侧「设备管理」页添加」。

页面底部有一条常驻提示,说明 Ping / 端口 / DNS 看「网络诊断」、SMB 与磁盘看「磁盘与共享」、第三方工具放 `Tools\` 后出现在「工具库」。

## 7. NAS 状态

对选中的设备做在线探测 + SSH 采集,顶部「设备」下拉默认选中**当前管理设备**(在此切换也会同步为当前管理设备)。

### 采集到什么

| 分区 | 内容 |
|---|---|
| 系统 | 系统类型(群晖 DSM / 威联通 QTS / UnRAID / TrueNAS / OpenWrt / Linux / Unix / 未识别)、主机名、CPU 核心数 |
| 运行 | 在线状态、在线时长(**实时走秒**)、负载(1/5/15 分钟)、温度 |
| 内存 | 总量与占用进度条 |
| 网络 | 默认网关、DNS、各网卡(名称、IPv4、状态、协商速率、**实时上下行速率**、累计流量) |
| 磁盘空间 | 各挂载点的已用 / 总量 / 占用百分比 |

几个细节:

- **在线状态**不等于「SSH 通不通」。判定顺序是:先 ICMP Ping;Ping 不通时再依次试 **SSH 端口 → Web 管理端口 → SMB 445**。所以 NAS 关了 Ping 也会显示在线 —— 这是刻意做的,避免「NAS 禁 Ping 就被判离线」。
- **网络与磁盘两个分区默认可折叠**,只预览前 3 行,点标题展开全部,再点「收起」复原。
- **内存占用口径**:按 `/proc/meminfo` 的 `MemTotal` 与 `MemAvailable` 计算,已用 = 总量 − 可用(含可回收缓存的算法)。老内核没有 `MemAvailable` 时回退用 `MemFree`。
- **磁盘挂载点美化**:群晖风格的 `vol1` / `volume1` 会显示成「存储空间1」并排在最前;`tmpfs`、`devtmpfs`、`overlay`、回环设备以及 `/proc` `/sys` `/dev` `/run` 下的挂载会被自动过滤掉。
- 内存 / 温度 / 核心数等读不到时显示 `—`,不报错。

顶部有一个**刷新**按钮。另外程序启动时已提前采集过一次,所以第一次进这个页面通常直接用缓存秒出,再在后台静默刷新。

采集命令**全部是只读命令**(`uptime`、`nproc`、`/proc/meminfo`、`df`、读温度、`/proc/uptime`、读网卡统计、`ip` 路由、`resolv.conf`),不会改动你的 NAS。

> 想了解失败原因:页面顶部状态行会直接写出形如「连接失败:…」加上修复建议(见 15 章)。

## 8. 网络诊断

两个工具卡片。

### 8.1 Ping 连通性测试

| 项目 | 说明 |
|---|---|
| IP / 主机名 | 默认自动填入当前选中 NAS 的地址,**可以改成任意地址**(比如路由器) |
| 次数 | 默认 4,有效范围 1–20,超出会被自动夹到范围内 |
| 开始 Ping | 开始测试,右侧显示转圈;结果显示在下方等宽字体区域 |

结果包含丢包率与最短 / 最长 / 平均延迟。注意:**Ping 不通不代表 NAS 离线** —— 很多 NAS 默认关闭 ICMP 响应。这种情况请看「NAS 状态」页的在线判定(它会回落去试端口)。

### 8.2 网速测试(Speedtest-x)

这是**测「你的电脑到 NAS 的局域网速度」**,不是测宽带。

**前置条件:NAS 上必须有一个 speedtest-x 类容器在跑,并且把宿主端口映射到了容器的 80 端口。**

工作流程:

1. 选择「NAS 设备」下拉(默认当前管理设备)。
2. 点**开始测速**。程序会先**扫描该 NAS 上已有的 Docker 容器**。
3. 找到了:自动解析它映射的宿主端口,识别是 `speedtest-x` / `LibreSpeed` 还是 `OpenSpeedTest`,在内置引擎里跑一次,结果直接显示在「延迟 / 下载 / 上传」三个大数字上。
4. 没找到:提示「未找到 speedtest-x 容器…」并**自动跳转到 Docker 管理页**,让你先部署。

其它细节:

- 容器**没在运行**时,程序会自动帮你启动它再测(因为停止的容器读不到端口映射)。
- 提示「未能发现容器的端口映射」,通常是创建容器时没用 `-p` 把宿主端口映射到容器 `80`,或者用的是 `host` 网络模式 —— 后者无法自动发现。
- 测速引擎是内嵌网页端(界面上有一条 1×1 像素的隐藏 WebView,你看不到),所以**数值与网页版完全一致**。
- 结果会记住。下次进这个页面会显示「上次测速 · HH:mm:ss」以及上次的数值。
- 失败情况:等待超过约 4 分钟会提示「等待超时」;页面加载失败会提示改用浏览器。
- 页面下方的**在浏览器打开网页版(可供局域网其他设备测速)**链接,会用系统浏览器打开同一个测速地址 —— 你可以把这个网址丢给手机 / 别的电脑测。

想自己也测一遍?部署命令示例(在 Docker 页部署容器时填):

| 字段 | 填什么 |
|---|---|
| 镜像 | `badapple9/speedtest-x` |
| 端口映射 | `9001:80`(宿主 9001 → 容器 80) |
| 重启策略 | `unless-stopped` |

> 本程序自带一个离线镜像包 `img\badapple9_speedtest-x(latest).tar`,可以在 Docker 页直接从本地导入,不需要 NAS 联网拉取。详见 10.4。

## 10. Docker 容器管理

页面顶部有「设备」下拉(默认当前管理设备),左侧是本页的二级导航:**概览 / 容器 / Compose / 本地镜像 / 网络**,右侧是内容区。顶部还有**部署容器**与**刷新**按钮。

> 前提:NAS 上已装好 Docker,并且你在设备里配好了 SSH(权限模式建议 root 会话或 sudo 提权,否则 `docker` 命令会 permission denied)。

### 10.1 概览

一屏看完:Docker 版本、容器总数、运行中、已停止、本地镜像数、网络数。

### 10.2 容器

每个容器一张卡片,显示:

- 状态圆点 + 名称 + 镜像名
- 右侧大字状态:`运行中` / `已退出` 等
- 运行时长 / 详细状态(来自 `docker ps` 的 STATUS 列)
- 端口映射
- 操作:**启动 / 停止 / 重启 / 日志 / 删除**

规则与注意:

- **启动和停止是互斥显示的** —— 运行中的容器只显示「停止」,已停止的只显示「启动」;「重启」只在运行中时出现。
- **日志**会弹出一个可选中复制的等宽字体窗口。
- **删除**是**强制删除**,确认框会明确告诉你「容器内未持久化的数据会一并丢失」。映射到宿主机的目录卷不受影响。

### 10.3 Compose

列出 NAS 上的 Compose 项目(含已停止的),每个项目可以**启动 / 停止 / 重启 / 下线**。

- **下线**会「停止并移除其容器与关联网络(数据卷保留)」,确认框里写明了这一点。
- **部署 Compose** 支持两种方式,二选一:
  1. 填 **NAS 上已有的 compose 文件路径**,例 `/volume1/docker/app/docker-compose.yml`
  2. 选择**本机文件** —— 程序会先把它上传到 NAS 的 `/tmp/nastb-compose/` 再执行 `up -d`

  > 只上传你选的**那一个**文件。文件里引用的相对路径(如 `build` 上下文、`.env` 文件)必须已经在 NAS 上存在,否则会失败。
- 程序会自动探测用 `docker compose`(v2 插件)还是 `docker-compose`(v1);两者都没有时会提示「NAS 上未检测到 Docker Compose」。

### 10.4 本地镜像

这一屏有上下两块。

**上块:本机镜像(`img\` 文件夹)**

程序目录下的 `img\` 文件夹里放的 `*.tar` 镜像包会在这里列出(名称、大小、修改时间),每项可以:

- **导入到 NAS** —— 上传 tar 到 NAS 后执行 `docker load`,上传过程会显示百分比进度
- **删除** —— 删除本机这个 tar 文件(有确认框)

当前自带的包是 `badapple9_speedtest-x(latest).tar`(约 465 MB),也就是「网络诊断」页测速要用的那个容器镜像。

**下块:NAS 端本地镜像**

列出 NAS 上的镜像(标签、ID、大小、创建时间),可以**删除**单个镜像,或点**清理悬空镜像**执行 `docker image prune -f`(确认框会写明「删除所有无标签的悬空镜像」)。

### 10.5 网络

列出 Docker 网络(名称、驱动)。内置网络会标注「内置」,且**不显示删除按钮**;只有可删除的网络才有「删除」按钮(带确认框)。

### 10.6 部署一个容器

点顶部**部署容器**打开对话框:

| 字段 | 说明 |
|---|---|
| 建议镜像 | 来自 `img\` 文件夹的 tar 列表。**点一下就把镜像填入镜像框,部署时会优先本地导入(自动上传 + `docker load`),不走联网拉取** |
| 镜像(仓库:标签) | 例 `badapple9/speedtest-x` 或 `nginx:latest` |
| 容器名 | 可留空,**留空会自动随机命名** |
| 端口映射 宿主:容器 | 例 `9001:80, 8080:8080`,多项用逗号分隔,可留空 |
| 重启策略 | `unless-stopped`(推荐:异常 / 开机自动拉起)/ `always` / `no`(不自动重启)。默认 `unless-stopped` |
| 部署前先拉取镜像 | 默认勾选。首次部署或更新版本时勾选;用本地 tar 导入时不需要 |

部署过程的状态会实时显示在页面状态行上(上传进度 → 拉取 / 创建 → 「容器已创建并启动:<名称>」)。失败会显示「部署失败:…」并给出原因(例如「远端没有 docker 命令,可能未安装或不在 PATH 中。」或权限不足提示)。

## 13. 数据、凭据与隐私

### 所有文件的真实位置

| 内容 | 路径 |
|---|---|
| 设备台账 | `%LocalAppData%\NasToolbox\devices.json` |
| 设备在线状态缓存 | `%LocalAppData%\NasToolbox\device_status.json` |
| SSH 主机指纹信任库 | `%LocalAppData%\NasToolbox\known_hosts.json` |
| 工具图标缓存 | `%LocalAppData%\MyToolbox\IconCache\` |
| 工具元数据 | 程序目录 `Metadata\tools.json` |

> ⚠️ 注意最后两项不同目录:图标缓存目录名是 **`MyToolbox`**(历史遗留),而设备数据在 **`NasToolbox`**。「关于」页把两者都写成了 `NasToolbox\IconCache`,是不对的。

### 密码是怎么存的

- SSH 密码、私钥口令、sudo 密码一律用 **Windows DPAPI(CurrentUser 范围)**加密后才写入 `devices.json`,**不以明文落盘**。
- 密文与**当前 Windows 用户 + 当前这台电脑**绑定。所以:
  - 把 `devices.json` 拷到别的电脑 / 别的 Windows 账号下,**解不出密码**(会当作没密码处理,需要重新填写)。
  - 想整个搬家,请至少重新填一次密码。
- 想彻底清除某台设备的凭据:编辑设备 → 勾选**清除已保存的密码 / 私钥口令 / sudo 密码** → 保存。这会同时清掉该主机的主机指纹记录。

### 主机指纹校验

程序会记录 NAS 的主机密钥指纹(OpenSSH 风格的 `SHA256:xxx`)。首次连接需要你确认并信任;之后如果指纹变了,会警告「主机指纹已变更」,提醒你「确认是同一台 NAS(未重装、网络无中间人)后再信任」。

> **需要知道的一个实现细节**:指纹的强制校验目前只在**「测试连接」**这条路径上生效。状态采集、Docker、SFTP 等实际业务通道会自动信任未知主机密钥且不写入指纹库。也就是说 —— **请务必在添加 / 编辑设备时用「测试连接」跑一次并确认指纹**,把信任关系建立起来;后续通道会沿用这次建立的记录。

### 网络行为

- 状态的在线判定:ICMP Ping + TCP 端口探测(SSH / Web / 445),全部对本机所在的局域网。
- 「NAS 状态」的 SSH 采集:执行的全是只读命令。
- Docker 操作:只在**你点按钮时**才执行对应命令。
- 本程序**不含**任何联网遥测、账号登录或云端上报。

## 14. 典型场景配方

### ① 早上起床先看 NAS 是不是还活着

打开程序 → 「首页」看设备列表的圆点。想更准就点**检测全部**。

### ② NAS 关了 Ping,但我想确认它在线

不用担心。在线判定在 Ping 不通时会自动去试 SSH / Web / SMB 端口。若仍显示离线,进「NAS 状态」页看顶部状态行里的具体失败原因。

### ③ 某块存储盘快满了

「NAS 状态」页 → 看**磁盘空间**分区(默认只显示前 3 行,点标题展开全部)。群晖的 `vol1` / `volume1` 会显示成「存储空间1」等友好名字。

### ④ 想知道 NAS 当前有多大流量

「NAS 状态」页 → 展开**网络**分区 → 每张网卡上有实时上下行速率(采集时做了 1 秒间隔的两次采样来算速率)。注意这是采集那一刻的瞬时值,不是持续监控。

### ⑤ 部署一个测速容器,然后用它测局域网速度

1. 「Docker」页 → **部署容器**
2. 在「建议镜像」里点 `badapple9_speedtest-x(latest).tar`,镜像名会自动填好
3. 端口映射填 `9001:80`,重启策略保持默认 `unless-stopped`
4. 点**部署** —— 镜像会从本地上传并 `docker load`,不需要 NAS 联网
5. 部署完成后到「网络诊断」页点**开始测速**

### ⑥ 把一个离线 tar 镜像导入到 NAS

「Docker」页 → 左侧选**本地镜像** → 在「本机镜像(img\ 文件夹)」里找到目标 tar → 点**导入到 NAS**。过程中会显示上传百分比。

### ⑦ 改过 NAS 的 SSH 密码,工具连不上了

1. 「设备管理」→ 编辑该设备 → 重新填 SSH 密码 → 保存(保存时会自动丢弃旧连接并重新握手)
2. 还是不行的,点顶部**断开 SSH** 强制清空所有缓存连接
3. 再用**测试连接**确认

### ⑧ 想给某台 NAS 单独改命令超时

设备编辑 → 「权限与高级」→ 命令超时(秒)。慢命令(如 SMART 全盘检测)可以调到 60 甚至更大。

## 15. 故障排查

### 15.1 SSH 连接类

「测试连接」会用清晰的标签告诉你失败类型。对照处理:

| 提示标签 | 含义与处理 |
|---|---|
| 配置缺失 | 点「编辑」补全 SSH 信息(地址、端口、用户名、密码或私钥) |
| 主机无法解析 | IP / 主机名不正确。主机名依赖路由器解析,**建议优先用 IP** |
| 端口未开放 | SSH 服务没开或被防火墙拦。群晖:控制面板 → 终端机和 SNMP → 启动 SSH;威联通:控制台 → 网络和文件服务 → Telnet/SSH |
| 连接超时 | 设备离线或网络不通。先确认 Ping 能不能通,再排查 VPN / 网段隔离 |
| 认证失败 | 用户名或密码被拒。群晖需用 administrators 群组账号;DSM 7+ 普通命令不需要 root,`smartctl` 等才需要 sudo |
| 私钥文件不可用 | 私钥路径不对。支持 `%USERPROFILE%` 等环境变量,例 `%USERPROFILE%\.ssh\id_rsa` |
| 私钥无效 | 私钥需为 OpenSSH 或 PEM 格式;带口令的私钥请在「私钥口令」里填 |
| 指纹未信任 | 首次连接该设备。核对指纹后点「信任此指纹并重连」 |
| 主机指纹变更 | 主机密钥与上次记录不一致(重装 / 换 SSH 服务 / 或存在中间人风险)。确认无误后再信任 |
| 服务器中断握手 | TCP 通了但握手被服务端断开。多为 SSH 算法协商失败,也可能是 fail2ban 封禁或 `sshd MaxStartups` 限流。可在 NAS 上看 `/var/log/auth.log` |
| 未知错误 | 用系统自带 OpenSSH 或 PuTTY 交叉验证一次,判断是工具问题还是 NAS 问题 |

### 15.2 常见现象速查

| 现象 | 可能原因与处理 |
|---|---|
| 刚打开时设备显示「检测中…」很久 | 启动时在后台自动检测全部设备,属正常。等一会儿,或点「全部检测」立即重测 |
| NAS 明明开着却显示离线 | NAS 关了 ICMP 且 SSH / Web / 445 都不通。检查 Web 管理端口是否填写正确;或确认设备是否在另一网段 |
| 「NAS 状态」页显示 `—` | 该指标没读到。常见于:容器 / 虚拟化环境读不到温度;老内核没有 `MemAvailable`;非标准 Linux 没装 `ip` 命令 |
| Docker 页提示「远端没有 docker 命令,可能未安装或不在 PATH 中」 | NAS 未安装 Docker,或 Docker 不在非交互式 SSH 的 PATH 中(可在设备上用绝对路径验证) |
| Docker 操作提示权限不足 | 权限模式改「sudo 提权」或「root 会话」后重试 |
| 状态采集 / Docker 一直连不上,但手动 SSH 正常 | 点「断开 SSH」清缓存连接后重试;确认端口和账号没变 |
| 测速提示「未找到 speedtest-x 容器」 | 还没部署。按 14 ⑤ 部署后再测 |
| 测速提示「未能发现容器的端口映射」 | 创建容器时没做 `-p 宿主:80` 映射,或用了 host 网络模式 |
| 测速「等待超时」 | 网络慢或容器异常。点「在浏览器打开网页版」用浏览器验证容器本身是否正常 |
| SMB「枚举共享」被拒 | 匿名枚举被禁用。先在资源管理器登录一次 `\\NAS的IP` |
| 工具库看不到工具 | 确认工具放进了 `Tools\分类名\` 子文件夹(不能直接放 `Tools\` 根下),且扩展名在支持列表内 |
| 工具库图标是空白方块 | 该 exe 提取不到图标,属正常降级;不影响启动 |
| 搜索框搜设备,回车却跑到工具库 | 直接敲关键词回车默认按工具搜索。请点选下拉里「设备 · 」开头的那一项 |
| 设备名后面出现 `(2)` | 两台设备的主机名相同,程序自动去重 |
| 换了电脑后设备提示密码无效 | DPAPI 加密与 Windows 用户 / 机器绑定,需重新填写密码(见 13 章) |

## 16. 当前版本尚未内置的能力

诚实说明:程序内的「关于」页和仓库根目录的 `README.md` 有一部分是早期版本写的,里面提到的以下功能**在当前代码里并不存在**,不要去找对应按钮:

| 旧描述里提到的 | 当前实际情况 |
|---|---|
| 设备行上的 一键 Ping / 打开 Web 管理 / WOL 唤醒 / 打开 SMB 共享 按钮 | **没有**。设备卡片上只有「编辑」「删除」「当前管理」 |
| Wake-on-LAN 唤醒 | **没有发送入口**。底层魔术包功能存在,但界面上只保留了 MAC 字段的格式校验 |
| SSH 终端(拉起 Windows Terminal / OpenSSH) | **没有**。请直接用工具库里的 PuTTY,或系统终端 |
| SSH 状态一键体检 / SSH 自定义命令执行面板 | **没有**。系统与运行信息请用「NAS 状态」页 |
| 常用 NAS 端口探测面板(10 个端口)/ DNS 解析面板 | **没有**。端口探测只在内部用于判断设备在线(SSH / Web / 445) |
| 图标缓存位置写 `%LocalAppData%\NasToolbox\IconCache` | 实际是 `%LocalAppData%\MyToolbox\IconCache` |

此外:

- **MAC 地址字段目前没有可见用途**(填了也不会有 WOL 按钮出现),它是为将来的唤醒功能预留的。可以留空。
- 程序没有自动更新、没有开机自启、没有系统托盘。
- 所有界面文字均为简体中文,没有多语言切换。

## 17. 术语表

| 术语 | 含义 |
|---|---|
| 台账 | 你登记在程序里的 NAS 清单,保存在 `devices.json` |
| 当前管理设备 | 功能页默认操作的那一台(见 3.3),同一时间只有一台 |
| 在线判定 | 先 Ping,不通再试 SSH / Web / 445 端口,任一通即判在线 |
| 主机指纹 | NAS SSH 主机公钥的 SHA256 摘要,用于识别设备重装与中间人 |
| DPAPI | Windows 的数据保护接口,本程序用它加密保存 SSH 凭据(绑定当前用户与机器) |
| 悬空镜像 | 没有标签、不再被引用的镜像层(`docker image prune` 清理的对象) |
| Compose 下线 | `docker compose down`:停止并移除容器与关联网络,数据卷保留 |
| speedtest-x | 一种自建测速页面(容器),本程序的局域网测速依赖它 |
